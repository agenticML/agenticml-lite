# Package 24.6: Phase 4 runbook fixes

Nov 12, 2026 · Supervisor plan · Release 3.0

## Goal

Make AWS roadmap Phase 4 (first accounts and data) runnable by the owner
without traps. A read-only check of every Phase 4 command against the code
(Nov 12, 2026) found that the runbook's first-admin path leaves an admin with
no workspace membership. It also found that it omits the startup `/setup`
link and several ordering traps. Fix the docs, and make `agenticml whoami`
print the workspace a key is bound to, which the README already claims it
does.

## Findings this plan acts on

1. The server logs `No admin user yet. Open <public url>/setup?token=...` at
   every start while the `default` workspace has no admin or owner
   (`webauth.py` `arm_setup`, about lines 422-437). The setup form creates a
   login without `@` (default `admin`), with a password of at least 12
   characters. The account becomes owner of `default` and gets
   `server_admin=1`, and the link is closed for good. No doc mentions this
   link.
   - The token is in memory, single-use and has no expiry, but it changes at
     every task start.
   - It works only on `https://app.agenticml.xyz`, because the cookie is
     `__Host-` and Secure and the Origin check is pinned to the public URL.
2. `accounts add X --server-admin` (README "Accounts" block and HOSTED.md
   "First server administrator") creates an account with no password and no
   membership. `users invite` then fails with "unknown user", and
   `bind_dashboard` needs a membership even for server admins
   (`access.py:186-198`). The README then makes the operator the owner of a
   customer workspace.
3. `users add` prints an invite only when it creates the account. For an
   existing account it only adds the membership. `users invite` resets the
   password to NULL.
4. A web invite cannot be redeemed once the account belongs to more than one
   workspace: `redeem_invite` calls `_reject_cross_workspace_credentials`
   without operator rights. So people set their password before a second
   membership is added, or the operator uses `users set-password` afterwards.
5. `workspaces create --owner L` needs `L` to exist already.
6. `keys create` needs `--user` to be a non-viewer member of `--workspace`.
   `--workspace` defaults to `default`, as it does for every `users`/`keys`
   command.
7. Exec commands lack `--region`/`--profile`, and `list-tasks` has no
   `--desired-status RUNNING`.
   - A one-shot `--command` is not run through a shell, so an interactive
     `/bin/sh` session is easier for several commands.
   - If `AGENTICML_SERVER_DATABASE_URL` were missing in the exec session, the
     CLI would fall back to a SQLite file at `/data/server/agenticml.db`.
     Check the environment once before the first command.
   - Pass `--public-url https://app.agenticml.xyz` to `users add` and
     `users invite`.
8. Sync state on the client (`runs/<id>/sync.json`) is keyed by host only, so
   one local store syncing to two workspaces on the same host reports
   `up to date` for the second workspace. Phase 4 works around this with one
   `AGENTICML_DIR` per workspace. The code fix goes to the backlog.
9. `agenticml login` keeps one key per host, so a second workspace key
   replaces the first. Use `AGENTICML_HOST`, `AGENTICML_API_KEY` and
   `AGENTICML_DIR` per workspace instead.
10. `agenticml whoami` does not print the workspace. `README.md` (around line
    301) says it does. `GET /v2/whoami` returns `workspace`.
11. `docs/THREAT_MODEL.md:47` claims "ECS Exec session logging", but the
    cluster has no `ExecuteCommandConfiguration`. Only CloudTrail records the
    `ExecuteCommand` call.
12. `docs/SERVER.md` (around line 518) says `agenticml sync` exits 3 on 401.
    Only `--follow` does; a one-shot sync exits 1.
13. 3.0.0 is not on PyPI, so training machines install from
    `git+https://github.com/agenticML/agenticml-lite@dev`.

### 24.6b Docs: runbook and guides (antigravity; facts from this plan)

1. `deploy/aws/README.md`, section "Accounts, Firebase and customers": keep
   the Firebase paragraph, then rewrite the operator part:
   - Export `AWS_PROFILE=agenticml-account AWS_REGION=us-east-2`.
   - Select the task with `--desired-status RUNNING` and a `None` guard, then
     check readiness with `describe-tasks` (`enableExecuteCommand`, the
     `ExecuteCommandAgent` must be `RUNNING`).
   - Open a shell with `--command /bin/sh`, then check the environment
     (`AGENTICML_SERVER_PUBLIC_URL`, the database host only,
     `AGENTICML_SERVER_OBJECTS`, `PGPASSWORD` set, and no
     `/data/server/agenticml.db`).
   - First admin: the `/setup` link from CloudWatch
     (`aws logs filter-log-events --log-group-name /ecs/agenticml-hosted --filter-pattern '"No admin user yet"'`;
     use the newest line). The `users add NAME --role admin --workspace default`
     path is the break-glass alternative.
   - Customer workspace: `accounts add` → `workspaces create --owner` →
     `users invite --public-url`, then `users add` for members, then
     `keys create --user --workspace`.
   - The order rule from finding 4, and `users set-password` as the fix.
   - The fact from finding 3, and that a server admin sees a customer
     workspace only as a member.
   - Keys and links are printed once. The session isn't logged, so keep
     secrets out of `--command` strings and never use `--stdin` passwords
     there.
2. `deploy/aws/README.md`: add a new section "Sync from a training machine",
   after the accounts section:
   - Install from `@dev`.
   - Per-workspace environment (`AGENTICML_HOST`, `AGENTICML_API_KEY` read
     with `read -rs`, `AGENTICML_DIR`).
   - `agenticml whoami` (now prints the workspace).
   - A small smoke script run from an empty directory, because lineage
     snapshots the project directory.
   - `agenticml sync --all`, and the `/w/<slug>/` dashboard URLs.
   - The `--reset` workaround for sending one run to a second workspace.
3. `docs/HOSTED.md` "First server administrator": the setup link first, with
   the break-glass CLI path. Remove the claim that a credential-less admin
   "can generate an invite".
4. `docs/THREAT_MODEL.md:47`: say that CloudTrail records `ExecuteCommand`
   calls and that sessions themselves are not logged.
5. `docs/SERVER.md` (around line 518): exit 3 under `--follow`, exit 1 for a
   one-shot sync. Near line 231, add the per-workspace environment pattern
   and the `login` one-key-per-host note.

## Constraints and conventions

- No AWS calls by agents. Docs must not contain real tokens, keys or
  passwords; use `alice@example.com` style placeholders.
- Commands in docs use `--region us-east-2 --profile agenticml-account`, or
  say once to export them.
- Merging this to `dev` changes `src/`, so it queues a deploy that waits for
  the owner's approval. The deploy restarts the task, and while no admin
  exists that also changes the `/setup` token.
