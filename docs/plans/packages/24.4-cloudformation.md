# Package 24.4 †: CloudFormation replaces Terraform

Nov 10, 2026 · Supervisor plan · Release 3.0 · Coder: Sonnet; second review:
supervisor (Codex and Cursor are disabled) · Size: M

Source: the [AWS deployment roadmap](../aws-deployment-roadmap.md), Phase 1,
and owner decisions of Nov 10, 2026. This plan replaces the Terraform half of
[package 24.2](24-aws-deployment.md):

- **CloudFormation, not Terraform.** No state bucket or lock table; AWS keeps
  the stack state.
- **One region:** `us-east-2`, hostname `app.agenticml.xyz`.
- **Deploys run from a GitHub workflow** (manual dispatch, protected `hosted`
  environment, OIDC role). The environment allows `main`, `dev` and `v*`
  tags only (set in GitHub by the owner, not in code).
- **No NAT gateway.** Fargate tasks run in public subnets with a public IPv4
  address for outbound traffic only; their security group accepts traffic
  only from the load balancer. RDS and EFS stay in private subnets.
- **DNS stays at Namecheap.** No Route 53 hosted zone or records. The
  owner adds two CNAME records by hand: the ACM validation record (once) and
  `app` → the load balancer's DNS name (after the first deploy).
- **Cost alerts.** A $100 monthly budget, an email for every $10 of spend
  with a per-service breakdown, sent to two addresses. Ops alarms go to the
  same two addresses.
- **Firebase and open sign-up come later.** The stack starts without them;
  turning them on is a configuration change, not a template change.
- **Data safety:** single-AZ RDS by default, deletion protection and a final
  snapshot on RDS, `Retain` on EFS, both buckets and the backup vault.

The image (`deploy/aws/Dockerfile`, `entrypoint.sh`, `limits.json`,
`requirements-hosted.txt`) and `scripts/hosted_smoke.sh` from 24.1 do not
change.

**Privacy:** the alert email addresses are given only as a parameter when
the owner deploys the bootstrap stack from a laptop. They must not appear in
the repository, the workflow, GitHub variables or test fixtures (use
`ops@example.com`-style placeholders).

## Goal

The owner can go from an empty AWS account to
`https://app.agenticml.xyz/healthz` with: one `aws cloudformation deploy` of a
small bootstrap stack from a laptop (adding one Namecheap record while it
waits), a few GitHub environment variables, one run of the deploy workflow,
and one more Namecheap record. Every later image or infrastructure change is
the same workflow run against a reviewed commit. Terraform and its CI job are
gone. Spend is reported by email every $10.

## Design

Two stacks in `us-east-2`.

### 1. `agenticml-hosted-bootstrap` (`deploy/aws/cloudformation/bootstrap.yaml`)

Created once by the owner with admin credentials. It holds what must exist
before the deploy workflow can run, plus account-level cost alerts.
`Transform: AWS::LanguageExtensions` (for `Fn::ForEach` over the emails).

**Parameters:** `AlertEmails` (`CommaDelimitedList`, required, 1–5
addresses), `MonthlyBudget` (`Number`, default 100), `CostStep` (`Number`,
default 10), `Hostname` (default `app.agenticml.xyz`),
`GitHubOidcProviderArn` (default empty), `GitHubRepo` (default
`agenticML/agenticml-lite`).

**Resources:**

- **ECR repository** `agenticml/lite-server`: immutable tags, scan on push,
  lifecycle keeps the last 30 images. `DeletionPolicy: Retain`.
- **GitHub OIDC provider**, created only when `GitHubOidcProviderArn` is
  empty (an account can hold only one provider for
  `token.actions.githubusercontent.com`).
- **Deploy role** `agenticml-hosted-deploy`, trusted only by
  `repo:${GitHubRepo}:environment:hosted` with audience `sts.amazonaws.com`.
  Permissions: ECR push/describe on the one repository (plus
  `ecr:GetAuthorizationToken` on `*`); CloudFormation `CreateChangeSet`,
  `DescribeChangeSet`, `ExecuteChangeSet`, `DeleteChangeSet`,
  `DescribeStacks`, `DescribeStackEvents`, `GetTemplateSummary` on
  `arn:${AWS::Partition}:cloudformation:${AWS::Region}:${AWS::AccountId}:stack/agenticml-hosted/*`
  (`ValidateTemplate` needs `*`); `iam:PassRole` on the CloudFormation role
  only, with `iam:PassedToService = cloudformation.amazonaws.com`;
  `ecs:DescribeServices` on the service ARN pattern. No ECS Exec, no direct
  ECS/RDS/IAM writes.
- **CloudFormation role** `agenticml-hosted-cloudformation`, trusted by
  `cloudformation.amazonaws.com` (condition `aws:SourceAccount`). Scoped by
  service: ec2 (VPC, subnets, security groups, routes, internet gateway,
  VPC endpoint, describe), elasticloadbalancing, ecs, rds, elasticfilesystem,
  s3, acm read (`DescribeCertificate`, `ListCertificates`), logs,
  cloudwatch (alarms only; the hosted stack has no SNS resources), backup and
  backup-storage, secretsmanager for the RDS-managed secret, kms as needed by
  RDS and Backup, ssm read for the parameter types CloudFormation resolves.
  IAM limited to roles named `agenticml-hosted-*` except the deploy and
  CloudFormation roles themselves (`CreateRole`, `DeleteRole`, `GetRole`,
  `PutRolePolicy`, `DeleteRolePolicy`, `GetRolePolicy`, `AttachRolePolicy`,
  `DetachRolePolicy`, `TagRole`, `UntagRole`, `UpdateAssumeRolePolicy`,
  `PassRole`), plus `iam:CreateServiceLinkedRole` for the ECS, ELB, RDS and
  Backup service-linked roles. Where an action cannot be scoped to a
  resource, use `*` and say why in a comment. Report it as a deviation if a
  working stack needs anything broader. No route53 permissions.
- **ACM certificate** for `Hostname`, `ValidationMethod: DNS`, **without**
  `DomainValidationOptions.HostedZoneId` (DNS is at Namecheap).
  CloudFormation waits on this resource until the owner adds the validation
  CNAME; the record shows in the stack events and in
  `aws acm describe-certificate`. It lives in bootstrap so the hosted stack
  never waits on a manual DNS step. `DeletionPolicy: Retain` (deleting it
  would force a new validation record).
- **Alerts topic** `agenticml-alerts` (SNS, no KMS so Budgets can publish),
  one email subscription per address in `AlertEmails` via `Fn::ForEach`.
  Topic policy allows `sns:Publish` from `budgets.amazonaws.com` and
  `cloudwatch.amazonaws.com`, both with `aws:SourceAccount` =
  `${AWS::AccountId}`, plus the account root (for the cost-step function
  role, which also needs an identity policy).
- **Budget** `agenticml-monthly` (`AWS::Budgets::Budget`): `COST`, `MONTHLY`,
  limit `MonthlyBudget` USD, `CostTypes.IncludeCredit: false` and
  `IncludeRefund: false` (so promotional credits do not hide spend).
  Notifications to the alerts topic: `ACTUAL` > 100 % and `FORECASTED`
  > 100 %. This is the safety net; the $10 steps come from the function
  below.
- **Cost-step function** `agenticml-cost-steps` (Lambda, `python3.12`,
  inline `ZipFile`, 128 MB, 60 s timeout, only stdlib and `boto3`), run
  daily at 06:00 UTC by an `AWS::Events::Rule` (or `AWS::Scheduler::Schedule`;
  pick one and say which). Environment: `TOPIC_ARN`, `STEP` (= `CostStep`),
  `BUDGET` (= `MonthlyBudget`), `STATE_PARAM`
  (`/agenticml/cost-alerts/state`). Logic:
  1. `ce` client in `us-east-1` (Cost Explorer's endpoint). Month-to-date
     `UnblendedCost`, `Granularity: MONTHLY`, from the 1st of this month to
     today (UTC), grouped by `SERVICE`, filter out `RECORD_TYPE` `Credit` and
     `Refund`. On the 1st of the month (start = end is invalid) skip the
     month-to-date query.
  2. Read state `{"month": "YYYY-MM", "step": n}` from the SSM parameter
     (missing → `{"month": <this month>, "step": 0}`).
  3. **New month:** if `state.month` is not this month, send a summary of the
     previous month (same query for that month: total and breakdown), then
     reset state to this month, step 0.
  4. `crossed = floor(total / STEP)`. If `crossed > state.step`, publish one
     message and save `step = crossed`. Subject:
     `AWS spend passed $<crossed*STEP> this month ($<total>)`. Body: total,
     budget and percent used, month-end forecast (`GetCostForecast`; omit the
     line if it raises `DataUnavailableException` early in the month), then
     one line per service sorted by cost, services under $0.01 dropped,
     and a link to the Cost Explorer console. Several steps crossed in one
     day give one message.
  5. Any other error: let it raise (Lambda logs it). Add a CloudWatch alarm
     on the function's `Errors` metric (≥ 1 in a day) to the alerts topic so
     a broken reporter is noticed.
  The whole inline source must fit the 4096-character `ZipFile` limit; if it
  cannot, stop and report rather than adding an S3 packaging step. Function
  role: `ce:GetCostAndUsage`, `ce:GetCostForecast` on `*` (Cost Explorer has
  no resource ARNs; comment), `ssm:GetParameter`/`PutParameter` on that one
  parameter ARN, `sns:Publish` on the topic, and basic logging to its own log
  group (14-day retention, created in the template).
  Cost: Cost Explorer API calls are $0.01 each; about 2 a day ≈ $0.60/month.
- **Outputs (exported):** `DeployRoleArn`, `CloudFormationRoleArn`,
  `EcrRepositoryUri`, `CertificateArn`, `AlertsTopicArn`. Export names
  `agenticml-hosted-bootstrap-<Output>`.

Why a separate stack: the ECR repository must exist before the first image is
pushed, the role CloudFormation uses must not live in the stack it updates,
the certificate needs a manual DNS step, and the budget is account-wide.

### 2. `agenticml-hosted` (`deploy/aws/cloudformation/hosted.yaml`)

Created and updated only by the deploy workflow through the CloudFormation
role. It is the Terraform stack, translated, with these changes:

- **Parameters:** `ImageTag` (required, the commit SHA), `Hostname` (default
  `app.agenticml.xyz`), `DesiredCount` (default 2, min 0), `MultiAZ`
  (default `false`), `FirebaseProject` (default empty), `FirebaseApiKey`
  (default empty), `OpenSignup` (default `false`, allowed `true`/`false`),
  `VpcCidr` (default `10.42.0.0/16`). No hosted zone, no email, no bucket
  names: CloudFormation names the buckets (so a retry after a failed create
  does not collide with retained buckets).
- Imports from bootstrap with `Fn::ImportValue`: `EcrRepositoryUri` (image =
  `<uri>:<ImageTag>`), `CertificateArn`, `AlertsTopicArn`.
- **Network (no NAT):** VPC with IPv6, internet gateway, three pairs of
  subnets in the first two AZs (`Fn::GetAZs`):
  - ALB subnets `10.42.0.0/24`, `10.42.1.0/24` (public, IPv6 as in
    Terraform);
  - task subnets `10.42.20.0/24`, `10.42.21.0/24` (route to the internet
    gateway; the service sets `AssignPublicIp: ENABLED`);
  - data subnets `10.42.10.0/24`, `10.42.11.0/24` (private, no internet
    route) for RDS and EFS mount targets.
  Separate ALB and task subnets keep `AGENTICML_SERVER_TRUSTED_PROXY` equal to
  the ALB subnet CIDRs only. Keep the S3 gateway endpoint on the task route
  table. No NAT gateway, no Elastic IP.
- **Security groups** as in Terraform: ALB 80/443 from anywhere (IPv4 and
  IPv6); task 8080 from the ALB SG only, egress all; RDS 5432 and EFS 2049
  from the task SG only.
- **TLS:** HTTPS listener with the imported certificate and
  `ELBSecurityPolicy-TLS13-1-2-2021-06`; port 80 redirects to 443. No DNS
  records.
- **ALB:** dualstack, idle timeout 300, `drop_invalid_header_fields`, access
  logs to the logs bucket under `alb/`. Target group: IP targets on 8080,
  health check `/healthz`, deregistration delay 120. The logs bucket policy
  lets ELB in `us-east-2` write (ELB account `033677994240` for this
  region; check the current AWS docs and cite them in a comment). A region
  mapping may list only `us-east-2` and must fail clearly elsewhere.
- **ECS:** cluster `agenticml-hosted` with Container Insights, log group
  `/ecs/agenticml-hosted` (30 days), task definition (512 CPU / 1024 MB,
  X86_64, EFS volume with transit encryption and access point IAM,
  `stopTimeout` 120, `PGPASSWORD` from the RDS-managed secret's `password`
  key via `MasterUserSecret.SecretArn`), service `agenticml-hosted` (Fargate
  platform 1.4.0, ECS Exec on, 100/200 deployment percents, circuit breaker
  with rollback, grace period 60, `AssignPublicIp: ENABLED` in the task
  subnets). Environment as in Terraform's `locals.environment`, except the
  Firebase variables are left out (`Fn::If` + `AWS::NoValue`) when
  `FirebaseProject` is empty. `OpenSignup = true` with an empty
  `FirebaseProject` fails before anything changes (a `Rules` assertion).
- **RDS:** as Terraform (Postgres 16, `db.t4g.small`, gp3 20→100 GB,
  encrypted, `rds.force_ssl=1` parameter group, managed master password,
  7-day backups, deletion protection, `MultiAZ` parameter, data subnets,
  not publicly accessible). `DeletionPolicy` and `UpdateReplacePolicy:
  Snapshot`.
- **EFS:** encrypted, generalPurpose/elastic, mount targets in the data
  subnets, access point uid/gid 10001 at `/agenticml` mode 0700, the same
  three-statement file system policy. `DeletionPolicy` and
  `UpdateReplacePolicy: Retain`.
- **S3:** objects bucket (versioned, SSE-S3, public access blocked,
  owner-enforced, TLS-only policy, noncurrent versions expire after 30 days,
  abort multipart after 7) and logs bucket (90-day expiration). Both
  `Retain`.
- **IAM:** execution and task roles `agenticml-hosted-execution` and
  `agenticml-hosted-task`, same policies and trust conditions as `iam.tf`.
- **Backup:** vault (`Retain`), daily plan (05:00 UTC, 35 days), backup role
  with the two AWS managed policies, selection of the EFS file system and the
  RDS instance.
- **Monitoring:** the same six alarms with the same thresholds, periods and
  missing-data handling as `monitoring.tf`, with alarm and OK actions to the
  imported alerts topic. No SNS topic or subscription in this stack.
- **Outputs:** `ServiceUrl`, `AlbDnsName` (the Namecheap CNAME target),
  `ClusterName`, `ServiceName`, `LogGroup`, `ObjectsBucket`, `LogsBucket`,
  `EfsId`, `DbInstanceId`, `TaskSecurityGroup`, `TaskSubnets`.
- Every resource that supports tags gets `Project=agenticml-hosted` (the
  workflow's stack-level tags are enough).

## Deploy workflow (`.github/workflows/deploy.yml`)

- `workflow_dispatch` with optional input `ref` (as now); `environment:
  hosted`; concurrency group `hosted-deploy`, no cancel; `permissions:
  contents: read, id-token: write`; the same pinned action versions as now.
- Steps: checkout `ref` (no persisted credentials); assume
  `vars.AWS_DEPLOY_ROLE_ARN`; ECR login; build-or-reuse the immutable `<sha>`
  image (keep the logic that tells a missing tag from other errors); then:

  ```sh
  aws cloudformation deploy \
    --stack-name agenticml-hosted \
    --template-file deploy/aws/cloudformation/hosted.yaml \
    --role-arn "$CFN_ROLE_ARN" \
    --capabilities CAPABILITY_NAMED_IAM \
    --no-fail-on-empty-changeset \
    --tags Project=agenticml-hosted \
    --parameter-overrides ImageTag="$sha" DesiredCount=... MultiAZ=... \
      FirebaseProject=... FirebaseApiKey=... OpenSignup=...
  ```

  Values come from `hosted` environment variables: `AWS_CFN_ROLE_ARN`,
  `AWS_REGION` (default `us-east-2`), `HOSTED_DESIRED_COUNT` (default 2),
  `HOSTED_MULTI_AZ` (default false), `HOSTED_FIREBASE_PROJECT`,
  `HOSTED_FIREBASE_API_KEY`, `HOSTED_OPEN_SIGNUP` (default false). Pass them
  through `env:` and quote them; never interpolate `${{ }}` into the script
  body. Empty Firebase values reach the template as empty strings.
- On failure print the last 30 stack events. After success print
  `AlbDnsName` and `ServiceUrl` from the stack outputs, and check the
  service's running count equals `DesiredCount` through `describe-services`.
- A configuration change is: change the variable, re-run the workflow with
  the deployed SHA. The image is reused; only the stack changes.

## Constraints and conventions

- YAML templates, 2-space indent, short-form intrinsics, a short comment only
  where the reason is not obvious (match the Terraform files' density).
- Logical and physical names keep the `agenticml-hosted` prefix so runbook
  commands (`--cluster agenticml-hosted --service agenticml-hosted`, log
  group `/ecs/agenticml-hosted`) keep working.
- No hard-coded region or account in resources; use `AWS::Region`,
  `AWS::AccountId`, `AWS::Partition` (the Cost Explorer client's
  `us-east-1` is the one exception; comment it).
- No secrets in templates, parameters or workflow variables. The Firebase
  web API key is public by design; the database password stays in the
  RDS-managed secret. No email addresses in the repository.
- Do not change server code, the Dockerfile, the entrypoint or the smoke
  test. If a template needs a server change, stop and report it.
- Do not commit or push; hand the diff back.

## Edge cases

- **First bootstrap run:** stays `CREATE_IN_PROGRESS` on the certificate
  until the validation CNAME is in Namecheap (usually 5–30 minutes after the
  record is added). `aws cloudformation deploy` may stop waiting before
  that; the stack keeps going and `aws cloudformation wait
  stack-create-complete` resumes the wait. The runbook says so.
- **Namecheap CNAME host:** Namecheap wants the host without the domain
  (`_abc123.app`, not `_abc123.app.agenticml.xyz.`). The runbook says so.
- **Email subscriptions** are pending until each address clicks the confirm
  link; alerts before that are dropped.
- **Cost Explorer** must be enabled once in the console; data appears within
  24 hours. Until then the function's query fails and its `Errors` alarm
  fires — expected on day one; the runbook says to enable Cost Explorer
  before the bootstrap deploy.
- **Budget near the estimate:** the planned stack costs about $100–110/month,
  so the $100 budget's `FORECASTED` alert may fire near month end. Changing
  it is a bootstrap parameter change.
- **First hosted run:** `aws cloudformation deploy` creates the stack. The
  image is pushed first, so tasks start on a real image.
- **Failed first create** deletes the stack except the `Retain` resources
  (buckets, EFS, backup vault) and leaves an RDS snapshot; the coder lists
  them for the runbook.
- **Bad image:** the circuit breaker fails the ECS deployment, the stack
  rolls back to the previous task definition, the workflow fails with stack
  events printed.
- **Rotating the managed DB secret** needs a new task deployment
  (`aws ecs update-service --force-new-deployment`).
- **OIDC provider already exists:** bootstrap parameter set → no provider
  resource; the role trusts the given ARN.
