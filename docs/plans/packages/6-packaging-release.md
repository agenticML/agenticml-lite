## Goal

Anyone can run the 2.0 server from a public, signed container image on a
laptop (Docker + `tailscale serve`) or on AWS ECS Fargate, following docs
that match the code, and the package is ready to release as
`agenticml-lite` 2.0.0. A smoke script proves the image works end to end.

Out of scope: tagging `v2.0.0` and publishing (a release step after this PR
merges and `dev` is merged to `main`, done only with the user's go-ahead),
the manual checks in section 8 of the release plan, anything from 2.1.

## What exists today

- `agenticml server serve --data D --host H --port P --public-url U`
  (`cli.py` `cmd_server_serve`, `server/app.py` `serve`). `--data` falls
  back to `AGENTICML_SERVER_DATA`, then `~/.agenticml-server`.
  `AGENTICML_SERVER_KEY` adds an env admin key named `env`. `--public-url`
  has no env fallback. SIGTERM shuts down gracefully (drain). Binds
  `127.0.0.1:8080` by default; with no keys it warns and serves only
  `/healthz`.
- First key: with no admin key and no env key, the server logs
  `No admin key yet. Open <url>/setup?token=<token> ...` (`webauth.py`).
- `agenticml server keys create --name N [--scope sync|admin]`, `list
  [--json]`, `revoke N`. They work while the server runs (`keys.lock`).
- `GET /healthz` → `200 {"ok": true}`, no auth, no Host check.
- Dashboard login: `POST /login` with JSON `{"key": ...}`, needs the
  `X-AgenticML-Request` CSRF header, admin keys only, sets
  `aml_session` (or `__Host-aml_session` when `--public-url` is https).
  Dashboard API: `/api/runs`, `/api/runs/{id}`, ... (`ui/server.py`).
- The dashboard runs `git` for code diffs (`ui/server.py`), so the image
  needs `git`.
- Version `1.0.0` in `pyproject.toml` and `src/agenticml/__init__.py`;
  `publish.yml` checks the tag against both.
- Workflows: `test.yml`, `publish.yml`, `publish-testpypi.yml`,
  `docs.yml`. Actions are pinned by major tag (`@v7`); keep that style.
- `deploy/systemd/` (package 5). Website: Astro Starlight in `website/`,
  sidebar sections autogenerated from `getting-started`, `guides`,
  `reference` in `website/astro.config.mjs`.
- No `docker/`, `SECURITY.md`, `docs/SERVER.md` or `docs/THREAT_MODEL.md`.

## A. Image, compose, smoke script, workflows, version (Codex)

1. **`--public-url` env fallback.** In `cli.py`, `--public-url` defaults to
   `os.environ.get("AGENTICML_SERVER_PUBLIC_URL")` (resolved at run time in
   `cmd_server_serve`, not at import time, so tests can set it). The
   explicit flag wins. Add `help=` text to `serve`'s `--data` and
   `--public-url` naming their env vars. Test: env var only, flag only, flag
   beats env; an invalid env URL fails the same way as an invalid flag.
2. **`docker/Dockerfile`.**
   - `FROM python:3.12-slim@sha256:<digest>`: resolve the current digest of
     the multi-arch index (`docker buildx imagetools inspect
     python:3.12-slim`) and pin it, with a comment showing the tag.
   - Multi-stage: a build stage that runs `pip wheel --no-deps` on the
     build context (or `python -m build --wheel`), and a runtime stage that
     installs only that wheel (`pip install --no-cache-dir`), so no source
     tree, tests or `website/` end up in the image.
   - `apt-get install --no-install-recommends git ca-certificates`, then
     clear the apt lists.
   - User `aml`, UID/GID 10001, no login shell, no home writes needed.
     `mkdir /data && chown 10001:10001 /data` before `VOLUME /data`, so a
     fresh named volume is writable by the user.
   - `ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
     AGENTICML_SERVER_DATA=/data`.
   - `EXPOSE 8080`, `USER 10001:10001`, `STOPSIGNAL SIGTERM`.
   - `HEALTHCHECK` using Python's `urllib` against
     `http://127.0.0.1:8080/healthz` (no curl in the image).
   - `ENTRYPOINT ["agenticml", "server", "serve"]` and
     `CMD ["--data", "/data", "--host", "0.0.0.0", "--port", "8080"]`.
     `--public-url` comes from `AGENTICML_SERVER_PUBLIC_URL`, so users never
     have to repeat the CMD.
   - OCI labels: `org.opencontainers.image.source`, `.licenses=MIT`,
     `.title`, `.description`; version via a build arg.
3. **`.dockerignore`** at the repo root: exclude `.git`, `.github`,
   `website`, `testbed`, `tests`, `docs`, `examples`, `scripts`, `deploy`,
   `**/__pycache__`, `*.egg-info`, `.venv`, `build`, `dist`, `.agenticml`,
   `.claude`. Keep `README.md` and `LICENSE` (the package build needs them).
4. **`deploy/compose.yaml`.** One service `server`, image
   `ghcr.io/agenticml/agenticml-server:2.0.0` with `build:` pointing at
   `../docker/Dockerfile` and the repo root as context, a named volume at
   `/data`, port `127.0.0.1:8080:8080` (loopback only; `tailscale serve`
   or a proxy fronts it), `AGENTICML_SERVER_PUBLIC_URL` from the
   environment with an empty default, `restart: unless-stopped`,
   `stop_grace_period: 30s`, `read_only: true` with a `tmpfs` for `/tmp`,
   `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`. Comments
   show how to read the setup URL (`docker compose logs server`).
5. **`scripts/server_smoke.sh`.** Runs from the repo root; needs `docker`,
   `curl` and a Python that has `agenticml` installed (default
   `testbed/.venv/bin/python`, overridable with `PYTHON=`). Steps:
   - build the image with tag `agenticml-server:smoke` (skip with
     `SMOKE_IMAGE=<ref>` to test a pulled image, for the release check),
   - start it detached on a random free localhost port, with a fresh
     temporary volume, `--read-only`, and an `AGENTICML_SERVER_KEY` admin
     key generated with `secrets.token_urlsafe(32)`,
   - wait for `/healthz` (timeout 60 s; on timeout print `docker logs`
     and fail),
   - check `/healthz` answers with an arbitrary `Host:` header (ALB health
     checks use the task IP),
   - create a sync key with `docker exec <c> agenticml server keys create
     --name smoke --scope sync --data /data`,
   - in a temporary `AGENTICML_DIR` and `AGENTICML_CONFIG_DIR`, create a
     small finished run with the Python SDK (a few scalars, one
     `log_text` or similar event), `agenticml login --host
     http://127.0.0.1:<port>` with the sync key on stdin, and
     `agenticml sync --all`,
   - `GET /v2/runs/<id>/state` with the sync key: 200, and the run's files
     are listed with sizes equal to the local files,
   - sign in to the dashboard (`POST /login` with the admin key, the
     `X-AgenticML-Request` header and a cookie jar) and `GET /api/runs`:
     the run id is listed,
   - a sync key on `/login` gets 403,
   - `docker stop` exits within the grace period and the container's exit
     code is 0,
   - `trap` cleanup removes the container, volume and temp dirs on any
     exit. Print `smoke: OK` at the end.
   Keys are never echoed; read them into variables and pass them on stdin
   or as headers.
6. **`.github/workflows/image.yml`.**
   - Triggers: `push` tags `v*`; `pull_request` with paths `docker/**`,
     `.dockerignore`, `pyproject.toml`, `src/**`,
     `scripts/server_smoke.sh`, `.github/workflows/image.yml`;
     `workflow_dispatch`.
   - Job `smoke` (all triggers): build for `linux/amd64` with buildx and
     `load: true`, then run `scripts/server_smoke.sh` with
     `SMOKE_IMAGE` set to the built tag (install the package into a venv
     at `testbed/.venv` first, as `test.yml` does).
   - Job `publish` (tags only, `needs: smoke`): permissions `contents:
     read`, `packages: write`, `id-token: write`. Check the tag matches
     `pyproject.toml` and `__init__.py` (same snippet as `publish.yml`).
     QEMU + buildx, log in to GHCR with `GITHUB_TOKEN`, build and push
     `linux/amd64,linux/arm64` with tags
     `ghcr.io/agenticml/agenticml-server:<version>` and `:latest`,
     `sbom: true`, `provenance: mode=max`. Then `sigstore/cosign-installer`
     and `cosign sign --yes ghcr.io/agenticml/agenticml-server@<digest>`
     (keyless, by digest from the build step's output).
   - `concurrency` per ref, like `test.yml`.
7. **`.github/dependabot.yml`.** `version: 2`; `docker` in `/docker`,
   `github-actions` in `/`, weekly, target branch `dev`, a small open-PR
   limit.
8. **Version 2.0.0.** `pyproject.toml` and `__init__.py`. Leave the
   classifiers alone. Grep the tests for `1.0.0` and update any that pin
   it.

## B. ECS example and website sidebar (Cursor)

1. **`deploy/ecs/task-definition.json`.** Fargate, `networkMode:
   awsvpc`, 0.5 vCPU / 1 GiB, one container `server` from
   `ghcr.io/agenticml/agenticml-server:2.0.0`, port 8080,
   `readonlyRootFilesystem: true` plus a non-persistent volume for
   `/tmp`, user `10001:10001`, `stopTimeout: 30`, environment
   `AGENTICML_SERVER_PUBLIC_URL=https://aml.example.com`, secret
   `AGENTICML_SERVER_KEY` from Secrets Manager (`valueFrom` ARN
   placeholder), EFS volume with `transitEncryption: ENABLED` and an
   access point (`authorizationConfig.iam: ENABLED`) mounted at `/data`,
   `awslogs` to a log group, container health check on `/healthz` with
   Python `urllib` (same as the Dockerfile). Placeholders are obvious
   (`<account-id>`, `<region>`, `fs-XXXXXXXX`, `fsap-XXXXXXXX`).
2. **`deploy/ecs/terraform/`** (`main.tf`, `variables.tf`, `outputs.tf`,
   `versions.tf`): an example, not a module, that takes an existing VPC,
   two private subnets, two public subnets, an ACM certificate ARN and a
   hostname as variables, and creates: the EFS file system (encrypted) with
   mount targets and an access point (POSIX user 10001, root directory
   `/agenticml` owned by 10001 with mode 0750), the Secrets Manager secret
   (value set out of band, not in Terraform state: create the secret
   resource only and document `aws secretsmanager put-secret-value`), the
   ECS cluster, task definition (same settings as the JSON), service with
   `desired_count = 1`, `deployment_minimum_healthy_percent = 0`,
   `deployment_maximum_percent = 100`, `enable_execute_command = false`,
   the ALB (HTTPS 443 with the certificate, HTTP 80 redirecting to 443),
   target group (port 8080, health check `/healthz`, matcher `200`),
   security groups (ALB from `var.allowed_cidrs`; task only from the ALB on
   8080; EFS only from the task on 2049), the IAM task execution role
   (pull logs and the secret) and task role (EFS client mount/write on the
   access point), the CloudWatch log group, and an AWS Backup plan for the
   EFS (daily, 35-day retention). `aws` provider `~> 5.0`, Terraform `>=
   1.5`. Comments say this is an example to adapt, single task only (the
   server holds a single-writer lock).
3. **`deploy/ecs/README.md`**: short: what it creates, the variables,
   `terraform init/plan/apply`, setting the secret, reading the setup URL
   or using the env admin key, the single-task rule, cost note. Keep it
   short; Antigravity writes the long guide in `docs/SERVER.md`.
4. **`website/astro.config.mjs`**: add a `Server` sidebar group after

## Edge cases

- Named volume vs bind mount: a host bind mount owned by another UID makes
  `/data` unwritable; `docs/SERVER.md` says to `chown 10001` or use a
  named volume. The server must fail with a clear message, which it
  already does (`prepare_data_dir`).
- `--read-only` root filesystem: the server writes only under `/data`;
  Python may want `/tmp` (tmpfs). The smoke script runs with `--read-only`
  to prove it.
- ARM builds under QEMU are slow; the smoke job builds amd64 only.
- The env admin key cannot be revoked from the Keys page (409); the docs
  say so.
- `AGENTICML_SERVER_PUBLIC_URL` empty string from compose means "unset":
  treat an empty value as `None`.
