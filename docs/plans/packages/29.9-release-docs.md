`dev` → `main` merge carries release-ready docs. The version itself is already

instead of after PyPI as the 29 plan said. Order the owner follows: merge this

## Approach, step by step

1. Install lines. Replace each git install with the PyPI form, keeping the
   extras exactly as each line has them today:
   - `pip install 'agenticml-lite[system] @ git+...@dev'` →
     `pip install 'agenticml-lite[system]'`
   - `pip install 'agenticml-lite @ git+...@dev'` → `pip install agenticml-lite`
   - `pip install -U 'agenticml-lite @ git+...@dev'` → `pip install -U agenticml-lite`
   - `server/install.md` line about `[hosted]`: say to install
     `'agenticml-lite[hosted]'`; drop "while 3.0 is only on GitHub".
   Remove every sentence that says 3.0 is a pre-release, not on PyPI, follows
   the `dev` branch, or that PyPI has only 1.0.0. Do not add version pins
   (`==3.0.0`) to user-facing install lines, except where a line explains the
   minimum version.
2. Raw URLs. Every `raw.githubusercontent.com/agenticML/agenticml-lite/<main|dev|v2.2.0>/...`
   in the files above → `/v3.0.0/...`. Rewrite the README and `docs/SERVER.md`
   sentence "fetched from `main` because there is no 3.0 tag yet. Once 3.0.0
   is released, use the tag that matches ..." to say the unit is fetched from
   the `v3.0.0` tag and to use the tag that matches the installed version
   (`pip show agenticml-lite`). `deploy/systemd/README.md`: same.
3. Releases page (`releases.md`):
   - "Which version should I use?" table: every row installs from PyPI; the
     local-only row is `pip install agenticml-lite`, the server and hosted
     rows keep `[system]` as today. Version column `3.0.0 from PyPI`.
   - Replace the paragraphs saying `pip install agenticml-lite` installs
     1.0.0 / 3.0 is a pre-release with: `pip install agenticml-lite` installs
     3.0.0; to stay on 1.0.0, `pip install agenticml-lite==1.0.0` (local only,
     cannot sync to a 2.x or 3.0 server).
   - Keep "A 2.2 client has not been checked against the hosted service. Use
     the 3.0 client." (AWS roadmap step 5.3 did not check it.)
   - `## 3.0` heading → `## 3.0.0`. Status: `Released Nov 17, 2026 (tag
