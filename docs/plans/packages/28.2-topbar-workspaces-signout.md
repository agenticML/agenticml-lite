# Package 28.2: Workspaces link and Sign out in every top bar

Nov 16, 2026 · supervisor plan · coder: Sonnet

## Goal

The owner asked (Nov 16, 2026): inside a workspace there is no button back
to the workspace list, and Sign out must be on every signed-in page.

Today:

- Workspace pages (`/w/<slug>/...`) and `/admin` show **Sign out** in the
  top bar, but nothing links to `/workspaces`. The only way back is the
  switcher inside Settings → Account, or the Admin page heading (server
  admins only). The breadcrumb goes to `#/` (this workspace's runs), and
  `/` redirects to the last workspace (the `aml_ws` cookie), so it does
  not help either.
- `/workspaces` (the picker, rendered in `routes.py::_workspaces_page`) has
  no Sign out and no "Signed in as". A user with no workspace, or an admin
  with no membership, lands there and cannot sign out.

After this package every signed-in server page has, in its top bar:
a **Workspaces** link to `/workspaces` (except on the picker itself) and
**Sign out** (except for identity-proxy sessions, as today).

## Approach

1. index.html + app.js: add `#nav-workspaces` and unhide it in
   `sessionReady` right where `#nav-settings` / `#nav-admin` are set.
   Remove the Admin heading's duplicate link.
2. Add `signout.js`, its asset entry and public route.
3. Extend `_workspaces_page` as above.
4. CSS only if the 375px check fails.
5. Tests, then the doc lines.

## Constraints and conventions

- Same top-bar order on every page: breadcrumb, Workspaces, Settings,
  Admin, session (label, Sign out), Theme. The picker has no Theme button
  and no Workspaces link (it is the workspace list); do not add them.
- Never build HTML with unescaped user values (`html.escape(..., quote=True)`).
- `/logout` keeps its CSRF rule (`X-AgenticML-Request: 1`, same-origin);
  no GET sign-out, no form POST without the header.
- No API or database change. Existing behaviour of `/`, `/workspaces`
  listing, Admin link visibility and the Settings Account card (its own
  Sign out stays) is unchanged.
- Zero horizontal page overflow at 375px on a workspace page (server admin,
  so every button shows), on `/admin`, and on `/workspaces`.
- Keep the diff small; do not refactor unrelated code.

## Edge cases

- Key session bound to one workspace: `/workspaces` lists only that
  workspace; the link is still shown (harmless, one entry).
- `env` principal (server env key): label "Signed in as env", Sign out
  shown (same as the dashboard).
- User with no workspace on `/workspaces`: Sign out shown.
- Identity proxy (`via == "proxy"`): label only, no button, no script, on
  both the dashboard (already) and the picker.
- Local `agenticml ui`: no `#nav-workspaces`, no session box (unchanged).
- Sign out from the picker lands on `/login`; `/workspaces` then redirects
  to sign-in (session cookie cleared).
