the second guard against cross-workspace leaks.

## Goal

`--database postgresql://...` runs the same server on Postgres: same
repositories, same migrations, same behaviour. The whole test suite runs on
SQLite and on Postgres in CI. On Postgres, every workspace-owned table has
a row-level security policy, so a query that forgets its workspace filter
still sees only the bound workspace, and a query with no workspace bound
sees nothing.

Out of scope: more than one server process (20; 19 keeps `server.lock`
and the in-process run/object locks on Postgres too), S3 (21), `pg_dump`
backups (23), AWS (24).

## 19.1 Backend and test harness

### `db/postgres.py` (new)

- `PostgresDatabase(url)`: imports `psycopg` lazily; missing →
  `DatabaseError("Postgres needs the [postgres] extra: pip install
  'agenticml-lite[postgres]'")`.
- Same public surface as `SqliteDatabase`: `dialect`, `transaction(write)`,
  `close()`, `closed`. A bounded idle pool (16, like SQLite) of
  `psycopg.Connection` objects with `autocommit=False`; a connection whose
  transaction failed in a way that leaves it unusable
  (`OperationalError`, `InterfaceError`, broken) is closed, never reused.
  No `psycopg_pool` dependency.
- Per connection on open: `SET lock_timeout = '5s'`, `SET
  statement_timeout = '60s'`, `SET idle_in_transaction_session_timeout =
  '60s'`, `SET TIME ZONE 'UTC'`, `application_name = 'agenticml-server'`.
- `transaction(write)`: `BEGIN ISOLATION LEVEL READ COMMITTED` (plus `READ
  ONLY` when not write); yields a `Tx` with the same methods as SQLite's
  (`execute`, `fetchone`, `fetchall`, `lock_row`, `advisory_lock`) and
  `rowcount` on the returned cursor. Nested transactions refused as in
  SQLite.
- Rows: a row factory returning a `Row` that supports `row[0]`,
  `row['name']`, `row.keys()` and `dict(row)`, like `sqlite3.Row`.
- Errors: lock timeout, deadlock, serialization failure →
  `DatabaseBusy`; everything else from psycopg → `DatabaseError("could not
  read or write database")`. Connection failure at start →
  `DatabaseError("could not connect to Postgres")`. **Never** include the
  URL, host, user or password, or psycopg's message (it can contain the
  host) in an exception text, log line or `server status` output; chain
  with `from None` for connection errors.
- Startup: `SELECT rolsuper, rolbypassrls FROM pg_roles WHERE rolname =
  current_user`; if either is true, log one warning: "row-level security
  is not enforced for database role <name>; use a role without SUPERUSER
  or BYPASSRLS". (The role name is not secret; the URL is.)

### Dialect (`db/dialect.py`)

Add `PostgresDialect` beside `SqliteDialect`, each with `name`:

- `placeholders(sql)`: `?` → `%s`, and a literal `%` → `%%`. Repositories
  never put `?` inside string literals (assert in a test that scans
  `repos.py`/`workspaces.py`/new repo modules for `'...?...'` literals).
- `migration(sql)`: `{{id}}` → `BIGINT GENERATED BY DEFAULT AS IDENTITY
  PRIMARY KEY`, `{{blob}}` → `BYTEA`, `{{real}}` → `DOUBLE PRECISION`.
- `lock_row(tx, table, where_sql, params)`: `pg_advisory_xact_lock(k)`
  where `k` is a signed 64-bit integer from SHA-256 of
  `"row:" + table + ":" + json.dumps(params)`. An advisory key, not
  `FOR UPDATE`, because the row may not exist yet (insert races).
- `advisory_lock(tx, name)`: `pg_advisory_xact_lock(k)` with `k` from
  `"name:" + name`.
- `upsert(...)`: same SQL as SQLite (`ON CONFLICT ... DO UPDATE SET
  c = excluded.c`) works on Postgres; keep one implementation.
- `migrate()` takes `advisory_lock('migrate')` first, so two processes
  starting at once apply migrations once.

### `db/__init__.py`

- `connect(url)` dispatches on scheme: `sqlite:///` (as today),
  `postgresql://` and `postgres://` → `PostgresDatabase`. Anything else:
  `DatabaseUrlError` naming the two schemes (not echoing the URL).
- `for_server_dir`: the registry key for Postgres is the URL (kept in
  memory only); `import_state` still runs (2.x files in the data dir import
  into whichever database is configured).
- `default_url` unchanged (SQLite).

### Portability audit of repositories

Every SQL statement in `db/` must run on both backends. Known spots to
check and fix (Codex reports each change):

- Type strictness: Postgres refuses text in integer columns and
  integer/boolean comparisons that SQLite accepts. `server_admin`,
  `email_verified`, `personal` stay `INTEGER` 0/1; bind Python `int`, not
  `bool`.
- `INSERT INTO t VALUES (...)` without a column list: replace with explicit
  columns (Postgres column order after `ALTER TABLE ADD COLUMN` matches,
  but explicit lists are safer after 18b/18c added columns).
- Check-then-insert in a write transaction without a lock: SQLite's single
  writer made it safe; on Postgres two transactions can both pass the
  check. Each such place takes the matching `advisory_lock` /
  `lock_row`, or uses `ON CONFLICT DO NOTHING` (for example `RunRepo._ensure`).
  List every write transaction in the report with the lock it relies on.
- `GROUP BY`/`ORDER BY` with non-aggregated columns, `LIMIT -1`,
  `||`/`IFNULL`, `rowid`, boolean literals, `LIKE` case rules: none
  expected; fix if found.
- Python migration `0003_workspaces.py` (and any later Python migration)
  must work on an empty Postgres schema.
- Timestamps stay ISO text; sizes `BIGINT`; `REAL` columns are
  `DOUBLE PRECISION`.

### Test harness

- Env `AGENTICML_TEST_DATABASE_URL` (a superuser/admin URL to a scratch
  database). Unset: every test runs on SQLite as today.
- Set: an autouse fixture in `tests/conftest.py` creates, per test, a
  fresh schema `t_<16 hex>` owned by a non-superuser role
  `agenticml_test` (created once per session, `NOSUPERUSER NOBYPASSRLS`),
  and sets `AGENTICML_SERVER_DATABASE_URL` to a URL for that role with
  `options=-c search_path=t_<hex>` (URL-encoded). The schema is dropped
  after the test. Subprocess servers inherit the env var.
- Tests whose subject is SQLite itself (WAL, file mode 0600, NFS refusal,
  the `agenticml.db` file path, corrupt-file handling, `sqlite:///`
  parsing) get `@pytest.mark.sqlite_only` and are skipped on Postgres with
  a reason. Tests that use **two data directories expecting two separate
  databases** in one test are adapted (each server dir gets its own schema
  through a helper), not skipped. Keep the `sqlite_only` list short;
  report it.
- `tests/server_db_helpers.py` gains `postgres_url()` / `on_postgres()`
  helpers.
- Running locally: `docker run --rm -d -p 55432:5432 -e
  POSTGRES_PASSWORD=pw postgres:16-alpine` and
  `AGENTICML_TEST_DATABASE_URL=postgresql://postgres:pw@127.0.0.1:55432/postgres`.

### CI (`.github/workflows/test.yml`)

## 19.2 Row-level security

### Migration `0006_rls.py`

No-op on SQLite (`dialect.name == 'sqlite'`). On Postgres, for every table
with a `workspace_id` column (`memberships`, `invites`, `keys`, `runs`,
`run_files`, `run_notes`, `audit_events`, `sessions`, `objects`,
`workspace_usage`, and any later one):

```sql
ALTER TABLE t ENABLE ROW LEVEL SECURITY;
ALTER TABLE t FORCE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS t_workspace ON t;
CREATE POLICY t_workspace ON t
  USING (workspace_id = current_setting('app.workspace_id', true)
         OR current_setting('app.workspace_id', true) = '*')
  WITH CHECK (workspace_id = current_setting('app.workspace_id', true)
              OR current_setting('app.workspace_id', true) = '*');
```

`dialect.enable_workspace_rls(tx, table)` (no-op on SQLite) is **required**
for any later migration that adds a workspace-scoped table. 0006 covers
tables that exist at 19.2; it will not run again for tables added
afterwards. A catalog helper flags any `workspace_id` table that lacks
FORCE RLS plus `<table>_workspace`.

`audit_events` and `sessions` rows with `workspace_id IS NULL`
(server-level) are visible only in `'*'` scope. `FORCE` makes the policy
apply to the table owner too. A test asserts that every table with a
`workspace_id` column has a policy (catalog query), so a new table without
one fails CI.

### Binding the workspace per transaction

- `Tx.bind_workspace(wid)` → `SELECT set_config('app.workspace_id', %s,
  true)` (transaction-local); `Tx.cross_workspace(reason)` → sets `'*'`.
  On SQLite both are no-ops. `Tx.bound` records the current binding.
- `with tx.cross_scope(reason):` sets `'*'` and restores the previous
  binding on exit. Use it when a caller-supplied transaction needs a
  brief cross-workspace query and then more work in the original scope.
  Transactions opened solely for cross-workspace work keep
  `cross_workspace`.
- Workspace-scoped repositories (`UserRepo`, `KeyRepo`, `RunRepo`,
  `NoteRepo`, `AuditRepo(wid)`, `MembershipRepo`, `InviteRepo(wid)`,
  `UsageRepo`, ...) call `bind_workspace(self.workspace_id)` first in every
  transaction they open (one helper, e.g. `self._tx(write)`), and when
  handed a `tx` they bind it too, then restore the caller's previous
  binding.
- Cross-workspace reads and writes are explicit and few, each calling
  `cross_workspace` with a reason string: key lookup by digest
  (`KeyStore.verify`), `InviteRepo.find_pending` by token, sessions,
  `AccountRepo.workspaces`, `WorkspaceRepo` list/create/delete, server-
  level audit, server-admin usage, migrations and `import_state`, workspace
  delete. List them in the report.
- A transaction that touches a workspace table without either call sees
  zero rows on Postgres. That is the intended failure mode; the suite on
  Postgres (run as the non-superuser test role) finds any missed path.

## Constraints and conventions

- No backend-specific SQL outside `dialect.py`, `postgres.py`,
  `sqlite.py` and migrations guarded by `dialect.name`.
- The base install does not import psycopg; `import agenticml.server`
  works without it.
- The database URL is never logged, printed, put in an exception text or
  an audit row; tests check this.
- Keep SQLite behaviour byte-identical (same answers, same files).

## Edge cases

- Postgres restarts mid-run: the broken connection is dropped, the request
  gets 503, the next request reconnects.
- `lock_timeout` hit: 503 `Retry-After` through the existing
  `DatabaseBusy` mapping.
- Database newer than the code: same `SchemaTooNew` refusal.
- URL with `sslmode=require` or other libpq parameters: passed through to
  psycopg unchanged.
- `postgres://` alias accepted.
- Role is superuser (local docker default): works, with the warning; RLS
  tests use the non-superuser role.

## Done when

Both backends pass the full suite (CI job green), and an RLS test shows a
query without `app.workspace_id` returns nothing.
